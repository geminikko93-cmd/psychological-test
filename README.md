# JP 숏폼 작업실

일본어 숏폼(YouTube Shorts·Instagram Reels) 제작을 돕는 **Windows용 로컬 웹 프로그램**입니다.
AI가 기획과 제작 재료를 준비하고, 최종 편집은 사용자가 CapCut에서 합니다.

```
주제 입력 → AI 기획 방향(접근 방식이 다른 후보) → 선택·수정 → 일본어 대본 + 한국어 의미
→ 타입캐스트용 낭독문 복사 → (타입캐스트 사이트에서 직접 음성 생성) → 음성 파일 넣기
→ 무음 정리 + 전후 비교 → 최종 음성 기준 자막 정렬 → 장면별 영상소스 → CapCut용 묶음 내보내기
```

## 1. 설치와 실행 (Windows)

1. Python 3.11 이상을 설치합니다(설치 화면에서 **Add python.exe to PATH** 체크). <https://www.python.org/downloads/>
2. 이 폴더의 **`setup.bat`** 을 더블클릭합니다(처음 한 번, 약 1~3분, 인터넷 필요).
3. **`start.bat`** 을 더블클릭하면 브라우저에서 `http://127.0.0.1:8765/` 가 열립니다.
   검은 창을 닫으면 프로그램이 종료됩니다.
4. (선택) 음성 인식 보조 자막 정렬을 쓰려면 **`install_whisper.bat`** 을 실행합니다.
   프로그램 약 100MB + 모델(기본 small) 약 480MB를 처음 사용할 때 내려받습니다.

- 프로젝트 데이터: `문서\JPShortsStudio\projects` (환경변수 `JPSS_DATA_DIR`로 변경 가능)
- API 키: 프로그램 폴더의 `.env`(권장, 아래 2장). 화면에서 저장하는 경우 `%APPDATA%\JPShortsStudio`에 Windows 계정 DPAPI로 암호화해 저장
- ffmpeg는 `imageio-ffmpeg` 패키지에 포함된 실행 파일을 씁니다(별도 설치 불필요).
- 처음에는 [프로젝트] 화면의 **예제 프로젝트 열기**로 흐름을 둘러볼 수 있습니다.
  예제의 기획·대본은 사람이 작성한 샘플이고, 예제 음성은 검증용 합성 음성(edge-tts)으로 **타입캐스트 음성이 아니며 게시용이 아닙니다.**

## 2. AI(앤트로픽 API 중개서버) 연결

### 가장 간단한 방법: `.env` 파일에 키 넣기

`setup.bat`이 프로그램 폴더에 `.env`를 만들어 줍니다(없으면 `.env.example`을 복사해 `.env`로 저장).
메모장으로 열어 `YOUR_API_KEY` 자리에 받은 키를 넣고 저장하면 끝입니다. 프로그램 재시작은 필요 없고, [설정] → [연결 테스트]로 확인합니다.

```
ANTHROPIC_AUTH_TOKEN=받은_API_키
ANTHROPIC_BASE_URL=https://codex.hungnguyen.codes
ANTHROPIC_MODEL=claude-opus-4-8      # 또는 claude-sonnet-5 / claude-fable-5 / claude-haiku-4-5-20251001
```

- `ANTHROPIC_AUTH_TOKEN`은 Claude Code 설정과 같은 의미로 `Authorization: Bearer`로 보냅니다(`APIKEY=` 이름도 인식).
- `.env`는 git에 올라가지 않고(`.gitignore`), 프로젝트·내보내기 파일에도 들어가지 않습니다. 저장·내보내기 때 키 문자열이 섞이면 막습니다.
- `.env`의 키가 화면에서 저장한 키보다 우선합니다. 화면의 서버 주소·모델 칸을 비워 두면 `.env` 값을 씁니다.
- 중개서버(new-api 게이트웨이)는 `/v1/messages`로 Anthropic Messages 형식을 받는 것을 확인했습니다(잘못된 키로 시험 → 401 "Invalid token"을 프로그램이 한국어로 안내). **실제 키로는 아직 시험하지 못했습니다.**

### 세부 설정 ([설정] 화면)

사용자 확인 결과에 따라 **Anthropic Messages 규격만** 구현했습니다(OpenAI 호환 규격은 미지원 — 그런 응답이 오면 오류로 알려줌).
코드에 주소·모델이 하드코딩되어 있지 않습니다.

| 항목 | 설명 |
|---|---|
| 서버 기본 주소 / 요청 경로 | 예: `https://(중개서버)` + `/v1/messages` |
| 모델 식별자 | 중개서버가 안내한 이름 그대로 |
| 인증 방식 | `x-api-key` / `Authorization: Bearer` / 사용자 지정 헤더 / 없음 |
| anthropic-version | 기본 `2023-06-01`, 보내지 않도록 끌 수 있음 |
| 추가 헤더 | 중개서버가 요구하는 헤더(비밀값으로 암호화 저장) |
| 최대 출력 토큰·시간 제한·스트리밍 | 기본 생성 설정 |
| 추가 요청 본문(JSON) | 예: `{"thinking": {"type": "adaptive"}}` — 모델이 지원하는 경우에만 |
| 입력/출력 단가(선택) | 입력하면 서버가 보고한 토큰 수로 **추정** 비용 표시. 비우면 비용을 표시하지 않음 |

키는 채팅에 적지 말고 `.env`(또는 [설정] 화면의 API 키 칸)에만 넣으세요. 넣은 뒤 **[연결 테스트]** 로 바로 확인됩니다.

- API 호출은 로컬 백엔드(`app/ai_client.py`)에서만 하며, 키는 화면·프로젝트·내보내기·로그에 들어가지 않습니다.
- 자동 재시도는 없습니다. 실패 시 이유와 해결 방법(예: 사용 한도 → `retry-after` 초 안내)을 보여줍니다.
- 요청 진행 중 [취소]로 중단할 수 있고, 시간 제한을 넘으면 중단합니다.
- 연결 전에는 AI 기능 버튼이 "연결 필요" 안내만 띄웁니다. 샘플 문구를 AI 결과처럼 보여주지 않습니다.

## 3. 구조와 기술 선택

| 구성 | 선택 | 이유 |
|---|---|---|
| 서버 | Python + FastAPI (127.0.0.1 전용) | 오디오 처리(numpy)·파일 관리·HTTP 호출을 한 언어로, 설치는 `setup.bat` 한 번 |
| 화면 | 빌드 없는 HTML/JS(ES 모듈) | Node 빌드·인터넷 CDN 없이 동작 |
| 오디오 | ffmpeg(imageio-ffmpeg) 디코딩 + numpy 분석 | WAV/MP3 모두 처리, 별도 ffmpeg 설치 불필요 |
| 일본어 | BudouX(문절 줄바꿈), pykakasi(읽기 추정) | 로컬 실행, 가벼움 |
| 자막 정렬(선택) | faster-whisper (로컬) | 쉼이 거의 없는 음성에서 정밀도 보강 |

  ai_tasks.py    응답 JSON 검증·정규화, 범위 밖 변경 차단, 이전 프로젝트 요약

  sources.py     내 파일 가져오기, Pexels/Pixabay 공식 API 검색·다운로드

## 4. 주요 기능 요약

- **기획**: 접근 방식이 다른 후보 제안(선택지 유무·개수·장면 수를 AI가 판단), 의견 반영 재제안, 직접 수정, 이전 기획 되돌리기. 이전 프로젝트 요약을 함께 보내 중복을 피함.
- **대본**: 화면 표시 일본어 / TTS 낭독 일본어 / 한국어 의미 / 장면 설명 / 발음·읽기 메모 / 표현 주의를 따로 편집.
  필요한 부분만 다시 만들기(첫 문장, 뻔한 결과, 자연스럽게, 빠르게, 소스 쉬운 장면, 이전 영상과 겹침) — 결과는 비교 화면에서 골라 적용, 범위 밖 변경은 자동 제외.
  AI 검토는 "원어민 검수 아님"으로 표시. 규칙 기반 표현 점검(과장·근거·업로드 약속·숫자 읽기·제목/설명 일관성)과 이전 프로젝트 유사 문장 검사. 대본 기록 되돌리기.
- **음성**: 낭독문 전체/장면별 복사(일본어만), 사용 음성·크레딧 기록, 파일 넣기(원본 보존·이전 원본 기록).
  무음 정리: 자연스럽게/빠르게/직접 설정, 무음 기준(자동·dB 지정), 남길 간격, 보호 여유, 구간별 유지·길이 지정, 대본의 '의도적 멈춤' 자동 반영, 파형·구간표 미리보기, 원본/정리본 A/B 및 구간 비교 듣기, 처리본 버전 되돌리기.
- **자막**: 최종 음성 기준 정렬, 구간 재생, 문구·시간 편집, 나누기·합치기, 문절 줄바꿈, 점검(겹침·음성 길이 초과·너무 짧음/빠름·줄 수), 휴대폰 화면 미리보기, 다시 맞출 때 수동 수정 보존 선택, 이전 자막 복원.
- **영상 (Google Flow)**: Flow의 Gemini Omni Flash 1.1(4·6·8·10초 클립)로 직접 생성하는 흐름.
  - **클립 계획**: 각 장면의 내레이션 구간(최종 자막 기준, 음성 전에는 대본 길이로 추정)을 문장 경계에서 나눠, 구간을 덮는 가장 짧은 허용 길이를 고름. 남는 꼬리는 CapCut에서 잘라냄. 길이는 클립마다 직접 바꿀 수 있음.
  - **프롬프트**: AI가 전체 공통 스타일(화풍·인물·색감)을 정하고 클립마다 영어 Flow 프롬프트 + 한국어 의미 + 초 단위 진행 + 권장 모드(텍스트 / 첫 프레임 / 재료)를 작성. 화면 속 글자·로고·말하는 인물·대사 없이(자막·내레이션은 CapCut에서) 9:16 구도. 클립 하나만 다시 만들기, 직전 프롬프트 되돌리기.
  - **생성 영상 넣기**: 클립마다 MP4를 넣으면 길이를 확인해 배치 구간보다 짧으면 경고. 마지막 프레임을 PNG로 뽑아 다음 클립의 첫 프레임으로 쓸 수 있음.
  - 자막 시간이 바뀌면 클립 계획이 '재생성 필요'로 표시됨. 다시 계산해도 구간이 같은 클립은 프롬프트·영상 연결을 유지.
  - Flow는 공식 자동화 연동을 쓰지 않고 사용자가 사이트에서 직접 생성(타입캐스트와 같은 방식).
- **기타 소스(선택, 접힌 메뉴)**: 내 영상·이미지 파일 넣기(열리는지 확인 후에만 확보), Pexels/Pixabay 공식 API 검색(키가 있을 때).
- **내보내기**: 점검 후 폴더+ZIP. 비공식 CapCut 프로젝트 파일은 만들지 않음.

```
00_먼저_읽기_CapCut_작업순서.txt     01_FINAL_최종음성_무음정리.wav     02_FINAL_자막_ja.srt
03_원본음성_타입캐스트_ORIGINAL.*   04_영상소스/S01_C01_8s_flow.mp4 …  05_장면표_시간_소스.csv
05b_Flow_클립_배치표.csv           06_대본_일본어_한국어.txt          07_타입캐스트_낭독문.txt
08_게시정보_제목_설명_크레딧.txt    09_프로젝트데이터(다시열기용)/      10_Flow_영상프롬프트.txt   파일목록.txt
```

## 5. 무음 정리와 자막 정렬 방식

- **무음 정리**: 10ms 단위 음량으로 소리/무음을 나누고, 긴 무음의 *가운데만* 잘라냅니다. 소리가 끝난 뒤(기본 100~130ms)와 시작 전(40~60ms)에는 보호 여유를 남겨 약한 어미·첫 자음이 잘리지 않게 합니다.
  재생 속도는 바꾸지 않습니다. 적용 후 ① 잘라낸 구간의 최대 음량이 기준보다 낮은지 ② 남긴 소리 구간 샘플이 원본과 완전히 같은지 자동 검증합니다.
  무음 안에 작은 소리가 있거나 앞뒤 소리가 약하게 끝나는 구간은 "확인 권장"으로 표시합니다. 무음 정리는 쉼을 늘리지 못하므로, 의도한 멈춤보다 실제 쉼이 짧으면 그렇게 알려줍니다.
- **자막 정렬(기본)**: 글자 수 비례 분배가 아닙니다. 실제 음성의 소리 덩어리와 쉼을 찾고, 문장별 예상 길이(모라 수)와 쉼 위치를 동적 계획법으로 맞춰 문장 경계를 실제 쉼에 놓습니다. 각 자막에 신뢰도(높음/보통/낮음)를 표시합니다.
  한 문장을 자막 여러 장으로 나눌 때는 문장 내부 쉼에 맞추고, 쉼이 없으면 "추정"으로 표시합니다.
- **자막 정렬(선택, 음성 인식 보조)**: faster-whisper가 내 PC에서 글자별 시간을 구하고, 이를 대본 읽기(히라가나)와 대조해 문장 시작·끝을 찾습니다. **자막 문구는 항상 대본의 화면 표시 일본어**이며 인식 결과로 바꾸지 않습니다.

## 8. 검증하지 못한 것과 남은 제약

- **실제 키로 중개서버 연동은 시험하지 못했습니다**(주소·형식은 확인, 키 미제공). 모의 서버로 Anthropic Messages 형식의 요청·응답·오류 처리만 확인했습니다. 실제 서버가 경로·인증·스트리밍을 다르게 처리하면 [설정]에서 맞춰야 할 수 있습니다.
- **실제 AI 출력 품질**(기획의 다양성, 일본어 자연스러움, 원칙 준수)은 실제 모델로 확인하지 못했습니다. 지시문(`app/prompts.py`)은 실제 응답을 보며 다듬을 필요가 있습니다.
- **타입캐스트 음성으로는 시험하지 못했습니다.** 검증용 일본어 음성은 edge-tts로 만든 것입니다. 타입캐스트 음성의 숨소리·잔향·쉼 길이에 따라 자동 무음 기준을 조정해야 할 수 있습니다(구간표의 "확인 권장"과 A/B 듣기로 확인).
- 문장 사이에 쉼이 거의 없는 음성에서는 기본 정렬의 신뢰도가 낮아집니다(낮음으로 표시). 이때 음성 인식 보조 정렬을 권장합니다.
- 읽기 추정(pykakasi)은 사전 기반이라 틀릴 수 있습니다. AI 일본어 검토도 원어민 검수가 아닙니다.
- Pexels/Pixabay 연동은 공식 API 형식대로 구현했지만 **실제 키로 시험하지 못했습니다.** 이용 조건은 각 원본 페이지에서 직접 확인해야 합니다.
- 배경음악이 섞인 음성은 무음 판단이 부정확할 수 있습니다(경고 표시).
- 처리본 WAV는 16비트로 저장합니다(24비트 원본은 16비트로 변환).
- CapCut 전용 프로젝트 파일은 만들지 않습니다(공식 지원 방식 미확인). SRT 가져오기 메뉴 이름은 CapCut 버전에 따라 다를 수 있습니다.
